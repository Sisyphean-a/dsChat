# 领域上下文

scope: workspace

## 通用语言

### 会话与回复

- **会话管理**：创建、选择、保存和维护对话及元信息的能力；不负责产生模型回复。
- **统一会话消息**：不依赖具体 Provider 的对话消息，可以携带用户、助手和工具结果。
- **流式回复**：模型回复以可见增量逐步到达的同一条助手消息。
- **流式状态**：流式回复期间可展示的进度，不改变回复正文或工具调用。
- **已停止的流式回复**：用户主动停止、尚未完成的流式回复；它不同于 Provider 请求失败。
- **Provider 请求失败**：Provider 的传输、响应或协议失败；它不同于用户主动停止。
- **空流式结果**：未产生文本增量或工具调用便结束的 Provider 回复；它是 Provider 请求失败。
- **最终回答**：工具轮次完成后的非空文本。使用了本地工具却缺少最终回答，不是成功回复。
- **全局系统提示词**：用户保存在设置中的全局回答规则。它不是聊天记录；每次回复启动时快照，非空时作为 Provider 上下文的第一条 system 消息。

### Provider 与工具

- **Provider 流**：把统一会话消息转为有序流式事件的能力；不执行本地工具轮次。
- **工具定义**：供模型识别可调用工具的结构化描述，不含执行结果。
- **工具调用**：模型请求执行具名工具的结构化指令，含工具标识和参数。
- **工具调用批次**：同一工具轮次中模型给出的全部完整调用，作为一个事件交给工具编排。
- **工具轮次**：模型提出调用、收到工具结果并再次请求模型的一次循环。
- **工具轨迹**：某一次工具调用从计划、执行到完成、失败或用户停止的可观察记录。
- **原生联网搜索**：Provider 自己提供的联网能力，不进入本地工具编排，也不产生本地工具轮次。

## 会话与持久化

- 所有设置始终保留本地副本；浏览器预览模式不访问 uTools 数据库。
- uTools 上传策略分为 `local-only`、`settings-only` 和 `all-data`。只有 `all-data` 同步会话和恢复用 session；从该模式切出时删除远端会话与 session。
- 当前会话记录它使用的配置 ID。恢复时若配置仍存在，切换到该配置；无效配置不能阻止会话恢复。
- 同一个会话的持久化写入必须串行，避免流式结束、异步标题和删除操作互相覆盖。
- `all-data` 双端同步以 `ConversationDoc.updatedAt` 和 `SessionDoc.updatedAt` 选择较新副本；旧 session 缺少 `updatedAt` 时以 `lastOutAt` 决胜。切出该模式前必须先将远端胜者写入本地，才可清理远端数据。
- 只有在 uTools 环境中才参与插件生命周期。离开插件会中断回复并记录时间；重新进入超过“对话”设置的会话恢复时长则不恢复上次会话。

## 回复与工具

- 发送前必须验证当前配置至少有 API Key、Base URL 和模型；工具总开关打开时还必须满足工具设置与 Provider 能力约束。
- 回复开始时快照当前 Provider 配置、思考等级、工具设置和全局系统提示词；发送中改变设置不得影响该回复。系统提示词按当前回合能力和工具定义动态构造，用户自定义规则作为附加回答规则。标题生成只使用首条用户文字与是否带图片的元信息，不直接读取图片。
- 对需要联网确认的时效性问题，模型应先调用 `get_current_time`，再将该工具结果用于构造当前搜索工具的时间条件；普通问题不调用时间工具，也不引入时间信息。
- 用户停止和插件中断使用中止信号结束正在进行的 Provider 或工具操作。停止、失败和成功是不同终态，均需写回会话。
- 本地工具按模型给出的批次顺序执行。单次工具执行失败（外部服务、传输错误或工具自身参数校验失败）不终止回合：失败原因写入工具结果交回模型，由模型如实说明或调整参数重试，工具轨迹与过程时间线仍标记失败；模型给出的工具参数无法解析、未知工具、重复调用和缺失最终回答仍必须显式失败，不能退化为未使用工具的普通回答。工具和 Provider 不设自动时间上限，用户停止或插件中断通过 AbortSignal 结束正在进行的操作。
- `customTools` 是预留数据形状，当前设置规范化会清空它，执行引擎也不支持它；任何非空且已启用的自定义工具必须在发送前被拒绝。
- **DeepSeek 网页工具**是本地内置工具，不是 Provider 原生联网，也不控制本地浏览器。`deepseek_search` 搜索公开网页，`deepseek_fetch` 读取网页正文；只在工具总开关开启且模型支持本地 Chat Completions 工具调用时提供。新用户的工具总开关与网页工具默认开启，只需配置已有 DeepSeek 密钥即可使用；旧设置保留明确关闭，缺少网页开关的旧配置不自动开启。开启后优先替代 Tavily，不要求 Tavily 密钥，也不会在失败时自动降级到 Tavily；关闭后恢复原有 Tavily 配置。
- DeepSeek 网页工具复用内置 DeepSeek 模型配置的 API Key（即使当前使用其他支持工具调用的模型），仅在请求准备阶段取运行时快照，不新增持久化密钥副本。工具服务固定为 `https://api.deepseek.com/v1/tools/search` 和 `/v1/tools/fetch`，不沿用模型代理地址、不跟随重定向，也不向被抓取网页发送密钥；代理专用密钥不保证可用。网页工具按次计费；空搜索结果有效，抓取无正文或服务错误必须显式失败。代码锚点：`chatAppRequestPreparation.ts`、`services/tools/deepseekWebTools.ts`、`services/tools/toolRegistry.ts`。
- 阿里云 Qwen 图片能力是受控的本地内置工具，不是 MCP Client：工具只接受 `attachment_id` 与任务参数，运行时只能从当前回合图片附件解析内容；不得接受模型生成的 URL、路径或 Base64。OCR、错误截图诊断和通用图片分析保持独立工具边界。

## 本机使用统计

- 设置中的统计从本机启用记录后累计，不补算历史会话，也不代表账号全平台账单。DeepSeek 输入、输出 Token 与缓存命中/未命中只取接口返回的 usage，不估算；缓存是输入的一部分，不能再加到输入总量。
- DeepSeek 请求数包含标题生成、每轮工具对话及已发起但失败或停止的请求；未返回 usage 或缓存明细的次数单独标示，不能解释成零消耗。工具次数在实际执行前累计，含失败和停止，不等于成功次数或计费次数；未执行的未知工具、无效 JSON 或重复调用不累计。
- 累计值独立保存在本机，不随会话删除，不进入 uTools 云同步。并发更新串行写入；存储失败显式提示，损坏数据不以零值覆盖。代码锚点：`services/usageStatistics.ts`、`composables/useChatApp.ts`、`components/SettingsStatisticsSection.vue`。

## Provider 与能力

- `chat_completions` 和 `responses` 是协议选择，不是 Provider 名称。可选协议必须由 Provider 能力档案明确声明：DeepSeek、Kimi、MiniMax 仅可用 `chat_completions`；OpenAI 与自定义配置可选两者。持久化的无效组合必须规范化为该 Provider 的默认协议。
- 本地函数工具调用只走 Chat Completions 适配器。Responses 适配器仅支持 OpenAI 原生联网搜索，不能假装支持本地工具轮次；阿里云 Qwen 图片工具同样只在支持本地 Chat Completions 工具轮次的配置中启用。
- Provider 不支持直接图片输入时，发送给 Provider 的消息不得携带图片附件；当前回合提供阿里云 Qwen 图片工具时优先走工具轮次，即使 Provider 能力配置声称支持图片，也不得将该附件直接发给 Provider；本地图片工具通过工具执行上下文取得当前附件。工具和 Provider 不设自动时间上限，均必须接收并遵循当前回复的 AbortSignal。所有 Provider、Tavily 和 Qwen 服务地址必须使用 HTTPS，URL 不得携带用户名或密码；Qwen 图片工具基础地址允许填写到 `/compatible-mode/v1`，运行时会追加 `/chat/completions`，也兼容完整 endpoint；图片 Data URL 在工具和 Provider 序列化边界都要校验。
- 预设模型列表是默认建议，不是已保存模型配置的白名单；规范化必须保留用户已保存的自定义模型 ID。模型 ID 解析忽略大小写并先按别名归一到当前模型；别名只影响能力与参数解析，不改写已保存的模型 ID。
- 模型或 Provider 的图片、推理、温度、原生联网与本地工具能力必须由注册表/能力档案声明，不能从名称猜测。
- 思考等级属于单个 Provider 配置，而非供应商全局偏好；只有内置档案明确支持的供应商、协议与模型组合才显示可选等级并发送参数。固定思考模型和自定义接口不得伪装成可控等级。
- 迁移缺少 `reasoningLevel` 的旧 OpenAI 配置时，历史默认的 `reasoning: false` 必须恢复为当前默认值；带有 `reasoningLevel` 的配置视为用户已明确选择，不得覆盖。

关联决定：[ADR-0001：按 Provider 协议隔离请求，保留本地工具编排边界](adrs/0001-provider-protocol-and-tool-boundaries.md)。
